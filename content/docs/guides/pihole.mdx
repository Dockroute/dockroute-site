The `pihole` provider writes **local DNS** entries through the
[Pi-hole v6 REST API](https://docs.pi-hole.net/api/): A/AAAA records as
hosts entries, CNAMEs as cname records. Use it for services that must
resolve only inside your network — dashboards, NAS, media servers — while a
second DockRoute instance publishes the rest through a public provider
([split-horizon](#split-horizon-with-a-public-provider)).

## Create an app password

In the Pi-hole admin UI: **Settings → Web interface / API → App password**.
Use that instead of your admin password — it can be revoked independently.

Pi-hole v6 is required (the v5 legacy API is not supported).

## Configure DockRoute

```yaml title="compose.yaml"
services:
  dockroute-lan:
    image: ghcr.io/dockroute/dockroute:latest
    environment:
      DOCKROUTE_PROVIDER: pihole
      PIHOLE_URL: http://192.168.1.5
      PIHOLE_PASSWORD: ${PIHOLE_PASSWORD}
      DOCKROUTE_DOMAIN_FILTER: home.lan
      DOCKROUTE_DEFAULT_TARGET: 192.168.1.10
    volumes:
      - /var/run/docker.sock:/var/run/docker.sock:ro
```

`DOCKROUTE_DOMAIN_FILTER` is **required** for this provider — startup fails
without it. Unlike the other providers it is matched against hostname
suffixes (`*.home.lan`), not provider zone names, because Pi-hole has no
notion of zones.

## Label your services

```yaml
  homarr:
    image: ghcr.io/homarr-labs/homarr
    labels:
      dockroute.enabled: "true"
      dockroute.hostname: "dash.home.lan"
      # dockroute.target omitted → DOCKROUTE_DEFAULT_TARGET
```

DockRoute creates the hosts entry `192.168.1.10 dash.home.lan` in Pi-hole,
and removes it when the container goes away (under the default `sync`
[policy](/docs/configuration/policies)).

## Ownership without TXT records

Pi-hole local DNS cannot store TXT records, so the
[TXT ownership registry](/docs/concepts/safety-model) does not apply here.
Instead, ownership is scoped by configuration — the same model Cloudflare
Tunnel ingress uses:

- Hostnames matching `DOCKROUTE_DOMAIN_FILTER` are treated as exclusively
  DockRoute-managed. [Sync policies](/docs/configuration/policies) keep their
  usual semantics inside that boundary.
- Anything outside the filter is never created, updated or deleted.
- Multi-hostname entries (`192.168.1.1 a.lan b.lan`) are left alone and
  logged, even inside the filter.

<Callout type="warn" title="The filter is the ownership boundary">
  Under the default `sync` policy, entries under the filtered domain that
  DockRoute did not create — including ones you added by hand in the Pi-hole
  UI — are treated as orphans and removed. Give DockRoute its own subdomain
  (e.g. `home.lan`) and keep manual entries outside it, or run
  `DOCKROUTE_POLICY=upsert-only`.
</Callout>

## Split-horizon with a public provider

Run one instance per provider; each only touches hostnames matching its own
filter:

```yaml title="compose.yaml"
services:
  dockroute-public:
    image: ghcr.io/dockroute/dockroute:latest
    environment:
      DOCKROUTE_PROVIDER: cloudflare
      DOCKROUTE_DOMAIN_FILTER: example.com
      CLOUDFLARE_API_TOKEN: ${CLOUDFLARE_API_TOKEN}
    volumes:
      - /var/run/docker.sock:/var/run/docker.sock:ro

  dockroute-lan:
    image: ghcr.io/dockroute/dockroute:latest
    environment:
      DOCKROUTE_PROVIDER: pihole
      PIHOLE_URL: http://192.168.1.5
      PIHOLE_PASSWORD: ${PIHOLE_PASSWORD}
      DOCKROUTE_DOMAIN_FILTER: home.lan
      DOCKROUTE_DEFAULT_TARGET: 192.168.1.10
    volumes:
      - /var/run/docker.sock:/var/run/docker.sock:ro
```

A container labeled `jellyfin.example.com` is published by the public
instance and skipped by the LAN one; `dash.home.lan` the other way around.
See [Multiple instances](/docs/guides/multiple-instances) for the general
pattern.

## Limitations

- **TTL** is ignored for A/AAAA (Pi-hole hosts entries have none) and
  honored for CNAMEs.
- **Tunnel labels** (`dockroute.tunnel.service`) are skipped with a warning —
  tunnels are a Cloudflare feature.
- **TLS**: point `PIHOLE_URL` at plain HTTP on the LAN or at a certificate
  your system trusts; self-signed-certificate options are not yet supported.
